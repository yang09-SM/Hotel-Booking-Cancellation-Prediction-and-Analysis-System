# 酒店预订取消预测系统 - 迭代升级规划 Spec

## Why
当前项目已具备基础的机器学习预测功能（4种模型）、RBAC权限管理、预订CRUD和统计分析。但对比 Booking.com、Kumo.ai、AWS Marketplace 等业界先进方案，以及最新学术研究（生存建模、概念漂移检测、图神经网络等），存在显著的功能差距和技术迭代空间。本规格旨在系统性地识别可升级方向，为项目下一阶段发展提供清晰的路线图。

## 当前项目现状分析

### 已实现的核心能力
| 模块 | 现状 | 技术栈 |
|------|------|--------|
| 机器学习模型 | 逻辑回归、XGBoost、LightGBM、神经网络（MLP） | scikit-learn, xgboost, lightgbm |
| 特征工程 | 缺失值填充、Label Encoding、StandardScaler | pandas, sklearn |
| 后端API | Flask RESTful API | Flask, SQLite |
| 权限控制 | RBAC三级角色（admin/manager/staff）+ JWT认证 | Flask-JWT |
| 前端界面 | 单页应用（侧边栏+内容区） | HTML/CSS/JS |
| 数据管理 | 预订记录增删改查、搜索、分页 | SQLite |
| 统计展示 | 基础统计指标（总数、取消数、平均提前期等） | 自定义统计 |

### 与业界方案的差距

**1. 机器学习模型层面**
- **缺少高级集成方法**：无 Stacking、Blending、Voting 等模型融合策略
- **无超参数优化**：当前使用固定超参数，未引入 Optuna/GridSearchCV/Bayesian Optimization
- **缺少深度学习模型**：无 LSTM/GRU（时序特征）、Transformer（注意力机制）、AutoEncoder（特征学习）
- **无可解释性工具**：无 SHAP、LIME、Partial Dependence Plot 等模型解释功能
- **无生存建模**：Booking.com 已采用 Survival Modeling 预测取消时间分布，而非简单二分类
- **无概念漂移检测**：学术研究显示 COVID-19 期间静态模型 AUC 下降 5-18%，需动态重训练机制

**2. 特征工程层面**
- **特征构造较基础**：缺少领域知识驱动的复合特征（如预订稳定性指数、渠道信任度得分、价格合理性特征）
- **无时序聚合特征**：缺少客户历史行为窗口统计（过去3月平均取消率、最近5次房价波动系数）
- **无外部数据整合**：未接入天气数据、节假日日历、会展排期、交通管制信息等
- **无特征交互挖掘**：学术研究指出特征交互（Feature Interaction）可显著提升性能

**3. 系统架构与工程化**
- **无模型版本管理**：缺少 MLflow/DVC 等模型生命周期管理工具
- **无自动化流水线**：训练-评估-部署全流程手动执行，无 CI/CD
- **无实时预测能力**：当前为批量离线预测模式，无流式/实时推理
- **无模型监控告警**：无法检测模型性能衰减或数据分布偏移
- **数据库局限**：SQLite 不支持高并发，生产环境应迁移至 PostgreSQL/MySQL
- **无缓存层**：频繁查询无 Redis/Memcached 加速

**4. 业务功能层面**
- **无动态定价建议**：未基于预测结果提供超售策略或价格调整建议
- **无客户画像系统**：缺少客户分群、忠诚度评分、流失预警等功能
- **无预警通知机制**：无高风险订单自动告警（邮件/短信/Webhook）
- **无批量操作优化**：批量预测缺少进度条、异步处理、结果导出
- **报表功能薄弱**：仅有基础统计，缺少趋势分析、对比报告、自定义仪表盘

**5. 前端体验**
- **可视化单一**：缺少交互式图表（ECharts/D3.js 高级用法）
- **无拖拽式分析**：用户无法自助构建分析视图
- **移动端适配不足**：响应式设计但触摸体验待优化
- **无暗色模式**：仅支持亮色主题
- **国际化缺失**：仅中文界面，无多语言切换

## What Changes - 迭代升级路线图

### Phase 1: 模型能力增强（高优先级）
- [ ] 引入 SHAP 可解释性分析模块，生成特征重要性解释报告
- [ ] 集成 Optuna 超参数自动调优框架，支持贝叶斯优化
- [ ] 实现 Stacking/Voting 模型融合策略，提升预测精度
- [ ] 新增 CatBoost 模型（对类别特征原生支持更好）

### Phase 2: 特征工程升级（高优先级）
- [ ] 实现领域知识驱动的复合特征构造（稳定性指数、价格偏差等）
- [ ] 引入时序聚合特征（客户历史行为窗口统计）
- [ ] 支持特征交互自动发现（二阶/三阶交叉特征）
- [ ] 接入外部数据源接口（天气API、节假日日历）

### Phase 3: 业务智能增强（中优先级）
- [ ] 构建动态超售策略推荐引擎（基于预测概率 + 房态）
- [ ] 实现客户画像与分群系统（RFM模型 + 取消风险评分）
- [ ] 开发高风险订单实时预警通知模块
- [ ] 设计自定义仪表盘与趋势分析报表

### Phase 4: 工程化与架构升级（中优先级）
- [ ] 集成 MLflow 模型版本管理与实验追踪
- [ ] 实现 A/B 测试框架（多模型在线对比）
- [ ] 引入 Redis 缓存层加速高频查询
- [ ] 数据库迁移至 PostgreSQL（支持并发 + JSON字段）

### Phase 5: 前沿技术探索（低优先级/长期）
- [ ] 研究 Survival Modeling（生存分析）替代传统分类
- [ ] 探索 LSTM/Transformer 时序预测模型
- [ ] 调研 Graph Neural Network（图神经网络）关联取消预测
- [ ] 实现概念漂移检测与动态模型更新机制
- [ ] 引入 AutoML（如 Auto-sklearn、FLAML）自动化建模

## ADDED Requirements

### Requirement: 模型可解释性增强
系统 SHALL 提供 SHAP 值分析功能，包括：
- 全局特征重要性排序（SHAP Summary Plot）
- 单样本预测解释（Force Plot / Waterfall Plot）
- 特征依赖关系可视化（Dependence Plot）
- 可导出解释报告（PDF/HTML格式）

#### Scenario: 用户查看预测解释
- **WHEN** 用户对某条预订进行取消预测
- **THEN** 系统返回预测结果的同时，提供该预测的 SHAP 解释（各特征贡献度）
- **AND** 用户可在统计分析页面查看全局特征重要性图表

### Requirement: 超参数自动优化
系统 SHALL 支持基于 Optuna 的超参数自动搜索：
- 支持贝叶斯优化、TPE、CMA-ES 等多种搜索算法
- 支持早停机制（Early Stopping）防止过拟合
- 支持交叉验证（Stratified K-Fold）确保评估稳健性
- 记录每次优化的完整实验日志（超参数、指标、耗时）

#### Scenario: 管理员触发模型重训练
- **WHEN** 管理员在模型管理页面点击"优化训练"
- **THEN** 系统使用 Optuna 自动搜索最优超参数组合
- **AND** 训练完成后自动保存最优模型并更新性能指标

### Requirement: 模型融合策略
系统 SHALL 支持 Stacking 和 Voting 集成方法：
- Stacking：使用元学习器（Logistic Regression/XGBoost）融合基模型预测
- Voting：支持软投票（Soft Voting）和硬投票（Hard Voting）
- 融合模型性能 SHALL 优于任一单模型

#### Scenario: 经理请求融合模型预测
- **WHEN** 经理选择"Stacking Ensemble"或"Voting Ensemble"进行预测
- **THEN** 系统返回融合模型的预测结果及置信区间
- **AND** 同时展示各基模型的独立预测结果供对比

### Requirement: 动态超售策略推荐
系统 SHALL 基于预测结果提供超售决策支持：
- 输入：当日预订列表 + 各订单取消概率 + 房间库存
- 输出：建议超售数量 + 预期收益 + 风险评估（超额预订概率）
- 支持不同风险偏好设置（保守/中性/激进）

#### Scenario: 经理查看超售建议
- **WHEN** 经理进入"收益管理"页面选择日期
- **THEN** 系统计算并展示该日的超售建议（建议超售X间，预期增收¥Y， walk风险Z%）
- **AND** 提供各高风险订单列表以便跟进干预

### Requirement: 客户画像与风险评分
系统 SHALL 构建客户维度分析能力：
- RFM 分析（最近入住频率、消费金额、预订频次）
- 客户取消风险评分（基于历史行为 + 当前预订特征）
- 客户分群（高价值稳定客 / 价格敏感客 / 高风险客等）
- 客户生命周期阶段识别

#### Scenario: 管理员查看客户分析
- **WHEN** 管理员进入"客户洞察"页面
- **THEN** 系统展示客户分群分布饼图、各群体取消率对比、TOP10 高风险客户列表
- **AND** 支持点击客户查看详细行为轨迹和风险因素分解

### Requirement: 高风险订单预警
系统 SHALL 提供主动式风险预警机制：
- 实时监控新创建的预订，自动评估取消风险
- 当取消概率超过阈值（可配置，默认70%）时触发预警
- 支持多渠道通知：站内消息、邮件、Webhook
- 预警记录可追溯，支持预警效果统计（预警准确率、干预成功率）

#### Scenario: 系统自动检测高风险订单
- **WHEN** 新预订被创建且预测取消概率 > 70%
- **THEN** 系统自动向经理角色发送预警通知（含预订详情和风险因素）
- **AND** 在预警中心记录该事件，标记为"待处理"

### Requirement: 外部数据整合
系统 SHALL 支持接入外部数据源以增强预测能力：
- 天气预报 API（OpenWeatherMap / 和风天气）：目的地天气状况
- 节假日日历：中国/全球主要节假日标识
- 会展/活动数据：当地大型活动排期（可选）
- 经济指标：GDP、旅游指数等宏观因子（可选）

#### Scenario: 预测时整合天气数据
- **WHEN** 用户输入预订信息进行预测（含目的地和入住日期）
- **THEN** 系统自动获取该日期目的地的天气预报
- **AND** 将天气特征融入预测模型，输出更精准的取消概率

### Requirement: 模型版本管理与实验追踪
系统 SHALL 集成 MLflow 进行 MLOps 管理：
- 记录每次训练的超参数、代码版本、数据版本、性能指标
- 支持模型版本注册与回滚
- 提供实验对比 Dashboard（类似 MLflow UI）
- 支持模型 Stage 管理（Staging → Production → Archived）

#### Scenario: 数据科学家查看实验历史
- **WHEN** 用户进入"实验管理"页面
- **THEN** 系统展示所有历史训练实验列表（按时间倒序）
- **AND** 点击某实验可查看完整详情（参数、指标曲线、混淆矩阵、特征重要性）
- **AND** 支持将任意历史模型部署为线上服务

### Requirement: 概念漂移检测
系统 SHALL 监控模型性能衰减和数据分布变化：
- 使用 PSI（Population Stability Index）监测特征分布偏移
- 使用 DDM（Drift Detection Method）监测预测误差变化
- 当检测到显著漂移时触发告警，建议重训练
- 支持滑动窗口训练策略应对渐进式漂移

#### Scenario: 系统检测到概念漂移
- **WHEN** 近期预测数据的 PSI 值超过阈值（默认0.25）或 AUC 连续下降
- **THEN** 系统在管理员面板显示漂移警告
- **AND** 建议启动模型重训练流程
- **AND** 记录漂移事件日志用于后续分析

## MODIFIED Requirements

### Requirement: 数据库升级
**现状**: 使用 SQLite 作为唯一数据存储
**修改为**: 
- 核心业务数据迁移至 PostgreSQL（支持并发、JSONB、全文检索）
- 保留 SQLite 作为开发/测试环境的轻量选项
- 新增 Redis 缓存层（热点数据、会话存储、预测结果缓存）
- 新增时序数据库选型（InfluxDB/TimescaleDB）用于指标存储（可选）

### Requirement: 前端体验升级
**现状**: 基础 HTML/CSS/JS 单页应用
**修改为**:
- 引入 ECharts 5.x 实现交互式数据可视化（热力图、桑基图、漏斗图等）
- 支持暗色/亮色主题切换
- 新增拖拽式自定义仪表盘（用户可选组件自由布局）
- 移动端体验优化（手势操作、底部导航适配）
- 国际化支持（i18n，中英文切换）

## 参考来源与对标分析

### 业界标杆方案
| 方案 | 核心优势 | 可借鉴点 |
|------|----------|----------|
| **Booking.com 生存建模** | 预测取消时间分布而非简单二分类；利用未完成数据训练；动态更新存量订单概率 | 生存分析建模、标签延迟问题处理 |
| **Kumo.ai 图神经网络** | 预测关联取消事件（天气突变导致批量取消）；捕捉网络效应 | 关联取消检测、图结构数据建模 |
| **AWS Marketplace (Mphasis)** | 云端部署即用；集成学习算法；SageMaker 托管 | 工程化部署、模型服务化 |
| **析客网络 XKAI** | 动态房态预测热力图；7-30天预测；PMS 对接；15分钟调价响应 | 业务闭环（预测→决策→执行）、外部数据整合 |

### 学术前沿方向
| 研究方向 | 来源 | 应用价值 |
|----------|------|----------|
| **Survival Modeling** | Booking.com AI Blog (2026) | 解决标签延迟问题，预测取消时间点 |
| **Concept Drift Detection** | Information Technology & Tourism (2025) | 应对疫情等黑天鹅事件，AUC 提升 5%+ |
| **Feature Interaction** | ACM DL (2025) | 特征交叉挖掘，提升判别力 |
| **Autoencoder 特征学习** | VU Business Analytics Thesis | 降维 + 特征学习，优于 PCA/MCA |
| **LSTM 时序预测** | 多个学术项目 | 捕捉时间依赖模式 |
